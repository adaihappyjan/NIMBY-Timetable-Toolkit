TRACK BLUEPRINTS
Follow the game map section by section, in stop order.
Add intermediate stops, inspect failures section by section and generate a new copy after adjusting the plan. Connection gaps are left near stations; platforms, points and signals are not changed automatically.

Intermediate stops · Connect from top to bottom

              
Origin → Intermediate stops 1 → Intermediate stops 2 → … → destination. Up to 40 stops; move entries up/down to reorder. Removing a stop changes only the plan, not the game station. Preview again after removal.

              

              
              
              
Find only built or blueprint stations already in the save; never create stations. Select complete endpoint names first. Candidates follow the railway route, not a straight line. There is no endpoint-distance cap, but large map areas may need separate batches. Existing intermediate stops are not used in this search.

              

                

                

                
                
              

            

            
            
            
            
            
            
            
            
            
            
            
            
            
            
            
            
          

          
          
Station names come from the current save; enter coordinates for unbuilt map locations. There is no endpoint-distance or total-length cap, but endpoints must be at least 0.1 km apart. Short searches expand locally; long or detouring routes explore railway-connected tile chunks from both ends instead of rejecting bounding boxes above 4096 tiles. The background task reports tiles checked. Data, time and 16384-tile safety budgets remain; reaching a budget does not prove disconnection. Find intermediate stations, select built/blueprint stops and preview sections. Up to 40 stops and 8000 double-track nodes, with coordinate and conflict checks. No antimeridian crossings or straight-line gap filling. Only three built-in track types are supported.

    Where does the data come from?
    Game map data is discovered from Steam libraries. Place GeoJSON in the save directory, its routes subfolder or the toolkit's routes folder, then read again. No individual uploads needed. Timetable-export JSON is not treated as a route file.
    The complete portable release includes routing components; no separate Node.js installation is needed. If missing, extract the complete package again. Source installs require Node.js 22+. GeoJSON and reference routes do not need it. Calculations run in the background without terminal windows or uploading saves/maps.
    Base-map data © OpenStreetMap contributors（ODbL） / OpenMapTiles. Map data is not engineering topology. Check generated routes in a new save copy first.

    Save after making changes
    
          
    
            
            
            
            
          
    
          
    
          
    
          
          
    Stop the service before changing its directory or port. A new directory does not move or delete the old cache. The size limit covers tile content; the database adds some overhead.     Usage rules and troubleshooting
    Online caching respects server expiry and revalidates on demand. Read-only caches may show old maps. HTTP 429 pauses all upstream requests and preserves the wait across restarts. Network errors are never stored as images. No regional batch downloading or global pre-caching.
