# 站名补写与自动跟进文件

## 为什么写过站名又变成未命名？

游戏显示的自动 / 模组名称不一定存为车站自定义名。工具箱只改新副本，不能改正在运行的游戏内存。生成 Names 副本后，如果仍继续运行原档，它的新自动存档仍会缺少这些名称。

正确顺序：游戏保存并导出时刻表 → 工具箱检查可补写站名 → 核对名称、缺名原因 → 确认写入新副本 → 在游戏中加载该副本 → 检查后继续保存。

站名来源为游戏 Timetable Export JSON，不能用地图 JSON 替代。读取完整合法 JSON，不依赖字段顺序或排版；最大 256 MB。按存档核验车站索引筛除误识别，使用完整 ID 且位置相距不超过 250 米的名称；导出缺名、坐标不符、同 ID 名称冲突均不猜测。未解决列表给出原因，也可每行手动填写 `0x…=站名`。

默认不覆盖已命名车站；“连已命名车站一并覆盖”是显式选择。预览绑定存档内容、名称映射和覆盖选项，发生变化须重做。无变化不创建空副本。写入后复读名称与车站索引、验证压缩往返，以不覆盖方式生成副本和清理识别清单。正式档不变。

## 自动跟进

默认开启；总览可关闭。每 5 秒只扫描文件名、大小和修改时间，不周期性解压存档。新文件至少经过两次观察且保持 3 秒稳定后才可跟进；零字节文件不选。稳定检测不是完整性证明，实际读取、写入仍有解析及指纹校验。

- 同一项目按保存文件名与 `Autosave N` 后缀归组，时刻表按 `项目名 Timetable Export…` 归组；文件时间较新不代表与存档内容匹配。
- 工具箱命名的 Names / Autotrack 等副本不会自动选中。需要处理副本时手动选择；手动选择会暂停跟进。
- 同名存档被覆盖也会检测。新文件出现在后台任务、编辑、预览期间，先提示，保留当前输入；点击“应用最新文件并重新读取”后检查结果失效。重读工作台 / 铺轨站点不会自动写入。
- 文件列表始终自动更新，手动固定旧档不会被强制换走。手动点击“自动选择最新”恢复跟进。
- 程序不会从不同项目拼接文件，不会把“最新”标为“已匹配”；涉及导出的写入仍需核对。

## 工作台能否直接点游戏的保存 / 导出？

本次核查未发现可调用的受支持接口，也未观察到当前游戏进程的 TCP 监听端口。按钮并不必然对应网络端口。[官方 NimbyScript 文档](https://wiki.nimbyrails.com/NimbyScript)说明其运行库没有文件 I/O 和网络功能，不能据此构造远程导出服务。这不证明所有版本都绝无隐藏接口，但不能把未验证的内部调用作为工具箱功能发布。

目前仍需在游戏中暂停、保存、导出一次；工作台接收落盘文件。没有注入游戏、扫描内存、模拟点击，也没有把工具箱自行生成的数据冒充游戏官方导出。
