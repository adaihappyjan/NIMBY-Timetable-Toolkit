# 线路工作台使用指南

本轮功能直接加入现有本地桌面窗口，不改变启动方式，不另开终端。

## 推荐操作流程

1. 在总览选择游戏保存完成后的存档。进入“线路工作台”，读取所选存档。
2. 搜索线路、表名、列车名或 ID，勾选需要处理的独立运营表。线路模板默认隐藏，不允许批量误改。
3. 批量配置只填写要修改的字段。时间留空保持原样；运营日可选每天、工作日、周末或自行勾选。
4. 车库候选是单站线路，必须由用户确认；勾选会将其既有指令固定为 x1，不创建新车库或进路。
5. 点击预览。确认每张表的新旧时间、日期、重复和偏移差异，再写入一个新存档。
6. 在游戏加载输出副本，检查出库、服务和回库。随后重新导出，使用“任务与验收”选择输出进行结构配对。

## 功能与边界

| 功能 | 已实现 | 不代表什么 |
|---|---|---|
| 线路工作页 | 搜索、对象分类、关联线路和车队、批量勾选、跳转完整编排器 | 不读取游戏实时内存 |
| 项目与草稿 | 后端持久保存选择、预设、地图点；按文件内容指纹与表 ID 保存编排器草稿，20 步撤销/重做 | 不把旧存档草稿自动套到改动过的存档 |
| 导出配对 | 最近 12 个 JSON 候选逐一完整结构核对，展示失败原因 | 结构兼容不等于生成时间相同；不强制绕过不匹配 |
| 批量运营 | 多表一份输出，日期、首班、回库、逐车偏移；可选分时段指令生成 | 不保证目标班距可由当前车队和轨道维持 |
| 七天接续 | 时间重叠、异站接续待确认、覆盖星期、无计划车辆，包含跨周 | 不知道空驶最短时长、寻路可达性、信号占用 |
| 共线协调 | 两支线同方向相邻站 ID 校验、入口运行时间、多个时段、半班相位、跨午夜、CSV | 计算目标序列，不自动写入复杂车队分配 |
| 车库时间轴 | 明确指定车库与容量，逐车计划区间、计划峰值、超容量、未访问指定库车辆 | 计划停库不是实际停库；没有记录显示未知 |
| 运营排行 | Accounting TSV，同对象粒度、同周期和时间戳；信号等待、晚点、满载、客流损失 | 满载发车比例不是平均载客率；departures 不一定是始发趟数 |
| 诊断脚本 | 仅对启用扩展的列车采样，未分配 / 已分配 / 计时停站 / 等信号，日志解读 | 1.19.10 编译与部分状态实测通过；不改变调度，不保证所有状态和复杂组合 |
| 模组安装 | 诊断包，以及本工具本次生成且带哈希凭证的规则/车辆 ZIP，禁止路径逃逸和同名覆盖 | 文件安装不等于游戏启用；对象扩展仍需在游戏内绑定 |
| 后台任务 | 单任务互斥防止并发写入、完成历史、增量进度、目录缓存；配对最多两个进程 | 写入不并行；不是完整调度模拟器；写入期间不能强制取消 |
| 验收 | 每批新旧快照、原文件指纹、压缩反读、清单；加载和运行分别用户确认 | 不能自动替用户确认游戏运行正常 |

## 分时段预设

在“高峰 / 平峰分段预设”中启用。每个时间边界对应一条 Max 客运指令；原客运 Order ID 用于第一段，其余段新增 ID，已有回库指令和其他表保留。

要求当前表恰好一条客运指令、没有堆积子项、已确认回库线路。系统会分配独立偏移组，避免把车库与客运偏移一起改掉。复杂表请打开完整编排器。

数值是该指令的逐车偏移，不是最终稳定班距；车队周转时长、进入站、校时站、峰平交界接续仍需验收。次日边界可用 24:00–48:00。

运营日控制指令在哪些日期开始，不会自动终止此前的无限循环。仅取消周末勾选不能保证周末停运；请检查最后一个运营日之后的回库 / 结束接续，并在七天图和游戏中核对。

## 诊断使用

在“诊断助手”安装预览版模组；游戏内启用 private mod，再在少量待排查列车上启用 `Toolkit read-only diagnostic`。本次会话手动打开脚本日志，短时运行后关闭，将 `NIMBY_DIAG|` 记录粘贴到工具箱。

控制器每 6 模拟秒调用，但脚本最多每 10 次调用记录一次；状态不变时每 50 次调用记录一次。仅保存自身诊断计数，不进行列车干预、瞬移、分配、信号覆盖或位置匹配修改。它是状态采样，可能漏掉短于采样间隔的状态变化。

接口依据：[官方 NimbyScript 文档](https://wiki.nimbyrails.com/NimbyScript)。2026-09-07 在游戏 1.19.10 的“控制器（高级）→ 开发”中确认 0 编译错误；启用 / 关闭日志触发的重编译同样通过。测试列车产生 ASSIGNED 与 TIMED_STOP 记录，稳定状态约每 5 模拟分钟采样，随后恢复行驶。未实测所有可能状态，不宣称全网运行验收通过。

实际操作入口：右上角模组管理启用模组 → 列车基本信息的“扩展”绑定到少量列车 → 控制器（高级）选择该脚本 → 开发 → 启用日志记录。测试后关闭日志。日志解析支持游戏的独立帧号 / 日期行与 L42 等源码行号。

## 教程与阅读体验

左侧“教程中心”或右上角“操作教程”提供八课：体检、批量配置、编排器、游戏验收、诊断、运营分析、副本清理、自动更新。支持搜索、直接跳转和本机已读进度；勾选已读只保存阅读状态，不执行修改。“舒适阅读”增大密集编排字段字号与间距。

## 数据保存与恢复

项目状态保存在用户配置目录的 `NIMBY_Timetable_Toolkit/projects`，不依赖随机浏览器端口。地图会导入当前浏览器来源中能访问到的旧规划点，不能跨端口主动读取其他浏览器来源的数据。

切换到内容改变过的存档后，原草稿仍保留，但不会自动恢复到新文件。需要沿用时，先导出原方案，再在完整编排器导入；ID、线路和原有指令约束继续生效。

任务临时文件、缓存与生成模组包沿用启动时清理策略（过期一天）；新工作台输出使用 `_Workspace_日期_时间` 命名，纳入既有副本回收规则，保留份数和天数设置继续生效。

## 本轮验证

- 原有测试与新增单元测试覆盖路径限制、凭证安装、草稿存储、缓存、星期更新、分段、同站方向、跨午夜、跨周、容量、统计空值和重复记录。
- 真实存档只读检查得到 19 张独立运营表、51 个线路模板和 393 列车。
- 使用系统临时目录中的真实存档副本，验证两张表一次写入、所有非目标运营组不变、原文件内容校验值不变、输出压缩反读一致。
- 在隐藏的隔离测试页面验证读取、搜索、勾选、运营日选择和修改预览，修复下拉标签问题及后台启动失败提示。
- 未覆盖正式存档；诊断扩展仅在独立测试副本的一列车上启用，完成约 27 模拟分钟的日志与运行观察。此测试不替代各线路首末班与回库验收。
