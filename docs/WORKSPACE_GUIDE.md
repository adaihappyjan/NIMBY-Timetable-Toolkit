# 线路工作台使用指南

本轮功能直接加入现有本地桌面窗口，不改变启动方式，不另开终端。

## 推荐操作流程

1. 在总览选择游戏保存完成后的存档。进入“线路工作台”，读取所选存档。
2. 搜索线路、表名、列车名或 ID，勾选需要处理的独立运营表。线路模板默认隐藏，不允许批量误改。
3. 批量配置只填写要修改的字段。时间留空保持原样；运营日可选每天、工作日、周末或自行勾选。
4. 车库候选是单站线路，必须由用户确认；勾选会将其既有指令固定为 x1，不创建新车库或进路。
5. 点击预览。确认每张表的新旧时间、日期、重复和偏移差异，再写入一个新存档。
6. 在游戏加载输出副本，检查出库、服务和回库。检查完成后暂停、保存，再在游戏内导出时刻表数据；回工具箱刷新文件，使用“任务与验收”选择这对文件进行结构核对。

## 需要时刻表数据时，先在游戏内导出

普通存档体检无需导出。需要游戏时刻表数据的功能，不能由工具箱代替游戏完成导出。

1. 在 NIMBY Rails 中打开目标存档，暂停游戏并保存。
2. 保持暂停、不修改线路或车辆，执行游戏内的时刻表数据导出，等待生成名称含 `Timetable Export` 的 `.json` 文件。
3. 回到“总览与体检”，点击右上角“刷新文件”，选择刚保存的存档和对应的游戏时刻表数据。
4. 点击“核对存档与游戏导出”。修改时刻表、线路或车辆后，需要重新保存并导出。

若列表为空，检查游戏导出是否完成，以及工具箱“存档目录”是否包含生成的文件。工具箱导出的线路图 JSON、运营报告或方案 JSON 不能代替游戏时刻表数据。选择最新文件也不保证两个文件匹配。

## 功能与边界

| 功能 | 已实现 | 不代表什么 |
|---|---|---|
| 线路工作页 | 搜索、对象分类、关联线路和车队、批量勾选、跳转完整编排器 | 不读取游戏实时内存 |
| 项目与草稿 | 后端持久保存选择、预设、地图点；按文件内容指纹与表 ID 保存编排器草稿，20 步撤销/重做 | 不把旧存档草稿自动套到改动过的存档 |
| 导出配对 | 最近 12 个 JSON 候选逐一完整结构核对，展示失败原因 | 结构兼容不等于生成时间相同；不强制绕过不匹配 |
| 批量运营 | 多表一份输出，日期、首班、回库、逐车偏移；可选分时段指令生成 | 不保证目标班距可由当前车队和轨道维持 |
| 七天接续 | 时间重叠、异站接续待确认、覆盖星期、无计划车辆，包含跨周 | 不知道空驶最短时长、寻路可达性、信号占用 |
| 共线协调 | 两支线同方向相邻站 ID 校验、入口运行时间、多个时段、半班相位、跨午夜、CSV | 计算目标序列，不自动写入复杂车队分配 |
| 车库时间轴 | 明确指定车库与容量，逐车计划区间、计划峰值、超容量、未访问指定库车辆 | 计划停库不是实际停库；没有记录显示未知 |
| 运营排行 | Accounting TSV，同对象粒度、同周期和时间戳；信号等待、晚点、满载、客流损失 | 满载发车比例不是平均载客率；departures 不一定是始发趟数 |
| 诊断脚本 | 仅对启用扩展的列车采样，未分配 / 已分配 / 计时停站 / 等信号，日志解读 | 1.19.10 编译与部分状态实测通过；不改变调度，不保证所有状态和复杂组合 |
| 模组安装 | 诊断包，以及本工具本次生成且带哈希凭证的规则/车辆 ZIP，禁止路径逃逸和同名覆盖 | 文件安装不等于游戏启用；对象扩展仍需在游戏内绑定 |
| 后台任务 | 单任务互斥防止并发写入、完成历史、增量进度、目录缓存；配对最多两个进程 | 写入不并行；不是完整调度模拟器；写入期间不能强制取消 |
| 验收 | 每批新旧快照、原文件指纹、压缩反读、清单；加载和运行分别用户确认 | 不能自动替用户确认游戏运行正常 |

## 分时段预设

在“高峰 / 平峰分段预设”中启用。每个时间边界对应一条 Max 客运指令；原客运 Order ID 用于第一段，其余段新增 ID，已有回库指令和其他表保留。

要求当前表恰好一条客运指令、没有堆积子项、已确认回库线路。系统会分配独立偏移组，避免把车库与客运偏移一起改掉。复杂表请打开完整编排器。

数值是该指令的逐车偏移，不是最终稳定班距；车队周转时长、进入站、校时站、峰平交界接续仍需验收。次日边界可用 24:00–48:00。

运营日控制指令在哪些日期开始，不会自动终止此前的无限循环。仅取消周末勾选不能保证周末停运；请检查最后一个运营日之后的回库 / 结束接续，并在七天图和游戏中核对。

## 诊断使用

在“诊断助手”安装预览版模组；游戏内启用 private mod，再在少量待排查列车上启用 `Toolkit read-only diagnostic`。本次会话手动打开脚本日志，短时运行后关闭，将 `NIMBY_DIAG|` 记录粘贴到工具箱。

控制器每 6 模拟秒调用，但脚本最多每 10 次调用记录一次；状态不变时每 50 次调用记录一次。仅保存自身诊断计数，不进行列车干预、瞬移、分配、信号覆盖或位置匹配修改。它是状态采样，可能漏掉短于采样间隔的状态变化。

接口依据：[官方 NimbyScript 文档](https://wiki.nimbyrails.com/NimbyScript)。2026-09-07 在游戏 1.19.10 的“控制器（高级）→ 开发”中确认 0 编译错误；启用 / 关闭日志触发的重编译同样通过。测试列车产生 ASSIGNED 与 TIMED_STOP 记录，稳定状态约每 5 模拟分钟采样，随后恢复行驶。未实测所有可能状态，不宣称全网运行验收通过。

实际操作入口：右上角模组管理启用模组 → 列车基本信息的“扩展”绑定到少量列车 → 控制器（高级）选择该脚本 → 开发 → 启用日志记录。测试后关闭日志。日志解析支持游戏的独立帧号 / 日期行与 L42 等源码行号。

## 教程与阅读体验

左侧“教程中心”或右上角“操作教程”提供九课：体检、批量配置、编排器、游戏验收、诊断、运营分析、副本清理、自动更新、地铁线网图。支持搜索、直接跳转和本机已读进度；勾选已读只保存阅读状态，不执行修改。“舒适阅读”增大密集编排字段字号与间距。

## 数据保存与恢复

项目状态保存在用户配置目录的 `NIMBY_Timetable_Toolkit/projects`，不依赖随机浏览器端口。地图会导入当前浏览器来源中能访问到的旧规划点，不能跨端口主动读取其他浏览器来源的数据。

切换到内容改变过的存档后，原草稿仍保留，但不会自动恢复到新文件。需要沿用时，先导出原方案，再在完整编排器导入；ID、线路和原有指令约束继续生效。

任务临时文件、缓存与生成模组包沿用启动时清理策略（过期一天）；新工作台输出使用 `_Workspace_日期_时间` 命名，纳入既有副本回收规则，保留份数和天数设置继续生效。

## 本轮验证

### 操作名称与结果边界

- “开始体检 · 免 JSON”只检查存档结构；“核对存档与游戏导出”需要玩家先在游戏暂停、保存，再导出 Timetable Export JSON。工具箱生成的报告、运行计划和线路图 JSON 不能替代它。
- 理论运行图依据线路模板推算。补充返程模式假设返程与去程对称；它不模拟信号、出入库、载客及进路冲突。生成图表不会替你配置游戏。车数按时长除以目标班距向上取整，仍需另计未包含的时间和备用。
- “时刻表配置”顶部可选择计算方案、停站写入、运营指令、车队迁移或历史恢复。新指令编号留空自动分配。线路模板时长不是车辆完整循环；发车偏移是逐车延后时间，例如 0 / 7 / 14 分钟。
- 车站坐标调整只修改位置字段，不移动站台轨道、信号及连线。
- 会计统计表 Accounting TSV 是另一类游戏导出；没有该数据时可跳过运营问题排行。周期分别为每日、每周、每月。

### 地铁线网图与导出

在线路图页载入游戏时刻表数据、勾选线路后，选择“地铁线网图”。列表支持名称/编号/沿线站名搜索、A–Z / Z–A 自然数字排序、编号、站数升降序、已选优先及“只看已选”。搜索和排序不改变勾选，隐藏的已选线路仍绘制和导出；全选、取消及仅载客线按钮只影响当前结果，“取消全部线路”才清空全部。图中共线区间分色并排、换乘站用圆环表示，线路交叉不等于换乘。同名但不同 ID 的车站不自动合并。缺坐标的站点保持断开并提示，避免画出不存在的连接。

这是一张非地理比例的示意图，不会修改游戏轨道。版式参考都市地铁图与铁路运营总览：连续长直段、水平/竖直/45°方向、圆角、均匀站距、沿线站名、普通站与双环换乘标记。长站名可倾斜排版，拥挤时使用引线或扩展画布，不再替换为底部数字索引。可调站间距、字号，并按 100% / 150% / 200% 查看。支持横向海报、纵向总览和大致地理方向；不虚构海岸线或缺失连线。SVG 保留绘制结果；线路图 JSON 保存原始经纬度、所选线路、显示坐标及绘图设置，不能作为游戏时刻表导出或自动铺轨路线导入。

铁路总览入口：样式选择“地铁线网图”，再将“线网图版式”切换为“铁路总览”。切换后自动适合窗口宽高，并重置图内滚动位置；图上方显示绘制结果或失败原因。100% / 150% / 200% 用于查看细节，图内可滚动。换乘站图标可选“大圆”或“胶囊形（圆角长条）”；胶囊随共线方向旋转并横跨平行线路，普通站仍使用小圆。两种图标均保存到 SVG，JSON 中的 `drawing.transfer_style` 和 `schematic_layout.transfer_style` 记录所选样式。

线路先按站序建立拓扑，再共同选择相邻区段走向，使用连续切线的贝塞尔转角连接。短区段保留方向，共线颜色维持相对顺序，不再每到一站都汇聚回中心点。示意图并非存档里的实体轨道/道岔拓扑，无法用它判断实际轨道是否通车。

“合并同线路分支”默认开启，适用于所有线路，不再仅对 REM 生效。名称去除常见分支后缀后相同或编号相同，且存在共用相邻站间时，会自动归组；同色、共用端点且至少共用两个相邻站间时也会归组。仅同色或共用起点不会合并。这是依据导出数据的推断，不是游戏中的正式线路关系；识别错误时可展开“同线路分支分组”，把已勾选线路设为同组、保持独立或恢复自动识别（包含搜索隐藏的勾选项）。先清空勾选，再选择分支可避免误操作。重新载入数据会清除手动分组。

同组采用第一条源线路的颜色，共用相邻站间只画一次；各分支站序分别保留，共用主干的普通站不算分支间换乘。与独立线路共用的车站仍标为换乘。取消勾选合并开关可查看多线显示。原始线路、选择状态、游戏存档不变，JSON 记录 `drawing.merge_branches`、`drawing.branch_groups` 及 `display_lines.source_ids/group_method`。本功能按站点 ID 与相邻区间识别，不会凭站名合并不同站，也不臆测快车跳站区间的物理轨道；需要用户指定分组。停用旧线路请取消勾选，否则其额外站序仍会保留。

“布局 → 网格布局（水平 / 垂直）”将各站安排在不重复的网格点上，并用直角连线；与都市地铁/铁路总览两种版式都能搭配。它不按真实经纬度比例显示，也不把单纯交叉当作换乘。常规布局保留圆角与大致八向走势，对很小的方向残差沿整个区段平滑处理，避免细小台阶。网格的间距、原点和显示坐标一并保存在 JSON 中。

常规布局另外检查不同线路区段的几何覆盖，以及普通站是否靠到无关线路上；必要时移动整段线路及其弯道锚点，只在真正共享的节点处汇合。同线路两条不同路径也分别保留：若旧总线经过某站、新分支跳过该站，两者同时勾选可能形成分叉后汇合的图形，不会为美观删除其中一条连接。站名引线优先避让线路和其他标注；无法全部避让时，界面单独提示引线问题，JSON 的 `label_leader_crossings` 与站名框冲突数分开记录。线条交叉本身不代表换乘。

线路图的导出文件夹仅对本页 SVG/JSON 生效。其他“下载/导出”按各功能提示或浏览器下载设置保存；未显示完整保存路径时，请确认文件实际落盘。站点标记 GeoJSON 只有点，自动铺轨需要连续 LineString 线路，二者不能互换。

### 清理与更新提示

自动清理默认关闭；开启后启动时直接按规则移入回收站。手动清理先预览确认；列表变化会拒绝执行，需重新预览。完整副本必须有匹配的生成记录及内容校验值；缺失记录、被玩家改写或勾选“永久保留”的副本会跳过。旧副本不按文件名强行补认。永久保留使用同名 `.keep` 文件，随存档一起保留。超过一小时的未完成 `.partial` 文件按临时文件规则处理。

更新失败分为旧文件已恢复、恢复不完整或状态未知，不再统一声称已回滚。恢复不完整时不要继续运行，保留日志和备份，重新解压完整包恢复。
