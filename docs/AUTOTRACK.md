# 自动铺轨

按起点、途经站、终点的顺序，沿游戏本地矢量铁路逐段寻找路线，生成**待建双轨蓝图**。
不是任意两点都一定有路：底图必须有连续路径，且满足范围、存档结构和冲突检查。
不改既有站台、道岔和信号，两端保留接轨空隙，最终接轨及工程验收仍在游戏中完成。

## 第一次操作

1. 在总览选择刚保存的存档，再打开“自动铺轨”。首次展示四步教学，以后可点“使用教学”重看。
2. 自动读取当前存档站点、Steam 库的 osm400.pmtiles 和本地 GeoJSON 路线。
3. 路线来源选“自动”。搜索起终站，选择包含 ID 的完整结果；同名站按 ID 区分。地图上尚未建站可输入 经度,纬度，例如 -73.5561007,47.8575037。
   需要沿线多站时，点“添加途经站”，从上到下填写站序；可上移、下移或删除，最多 38 个途经站（总共 40 站）。多站模式逐段使用全长，起终里程裁剪暂不适用。
4. 选择现实铁路过滤器；默认包括铁路、轻轨、地铁、电车、窄轨、单轨和缆索铁路。底图未收录的类型不会凭空出现。
5. 结构默认“自动”：无桥隧标记时使用地面，有标记时保留桥梁 +1 / 隧道 -1 层。也可强制整段地面、高架或隧道。
   自动结构下可选“水域 / 道路预避让”，界面默认选局部 +1，也可选 -1 或关闭。读取线路走廊内本地水面、河流和地面道路，保守检测相交 / 贴近，只改变新增地面节点，保留已识别桥隧；新层级使用对应桥梁 / 隧道速度类型。强制整段结构时关闭此项。
6. 地面、桥梁、隧道分别选择中速 160 / 高速 350 / 电车 60 km/h，默认均为中速。这里只是轨道类型上限，不保证曲线上的实际速度。
7. 点击预览，检查每个相邻站区间的路线、站点吸附距离、桥隧、避让及警告。失败区间会单独列出原因，成功区间仍显示在地图上。部分通过时，勾选“仅生成通过区间，跳过未通过区间”，再确认游戏内验收提示，即可把剩余区间蓝图一次写入一个新测试存档。失败区间整段留空，不会跨过失败站点或用直线补连；全部失败时不能生成。
   也可在失败区间下删除相关站点，或修改坐标、铁路类型，再重新预览。删除仅从方案移除，不会删除游戏内车站，但会重新连接它前后的站；这与保留缺口的“部分生成”不同。改参数会清除部分生成确认，不能复用旧预览。
   后续区间会避让前面准备生成的轨道；各站附近可能留有空隙，仍需游戏内手动接站和信号。失败原因可能来自底图断路或轨道冲突，不一定是该站本身的问题。写入时再次核对预览指纹；底图中途改变、存档结构未知或预览变化不能用“部分生成”绕过。
8. 游戏内保存现有进度，加载新副本，暂停检查弯道、坡度、净空、桥隧边界，再小范围试建、手动接轨和配置信号。

例如 A→B 通过、B→C 失败、C→D 通过：部分生成只生成 A→B 和 C→D，两段之间保持断开。生成结果和同名 `.manifest.json` 清单记录通过的区间编号、跳过的起终站及原因。编号字段 `index` 从 0 开始，界面编号从 1 开始。“导出预览方案”保存的是 JSON 报告，不是可直接在游戏中加载的蓝图；可加载的蓝图位于生成的新 `.nimbyrails5` 存档中。

部分生成以相邻站点区间为单位。单一区间中部存在冲突时，不会擅自切碎该区间、跳过未知结构或截断桥隧来强行生成；可增加合适的途经点或调整范围后重新检查。

耗时读取、寻路和写入在后台运行，不弹终端。写入阶段禁止强制取消。不会上传存档或底图，不会覆盖输入。
教学已读状态保存在工具箱用户设置目录，不依赖浏览器随机端口；更新后仍保留。

### 水域 / 道路预避让的范围

这是本地底图近似，不是读取游戏实时的红色冲突标记。水面多边形保留孔洞，河流和道路检测穿越与贴近；高架 / 隧道道路不作为地面障碍。水域安全带 6 米，普通道路 12 米、主干道 18 米（含双轨余量），并非游戏真实道路宽度。道路直角穿越也可能被保守避让，某些可建路段因此会多建桥隧。

游戏的层级在控制点之间的中点切换，因此命中路段的两个地面端点都升降，避免只抬中间一点、两侧仍在水里；不插入碎节点、不挪动路线、不改变既有存档轨道。区段较长时桥隧可能延长，需核对成本和线形。不会用此功能绕过既有轨道冲突保护。

每段最多读取 4096 个实际走廊瓦片、10 万要素、256 MB 压缩读取 / 3000 万字符解码结果，阶段预算 120 秒；超过限制会报告该段失败，不假装已检查。底图发生变化则整份方案要求重新预览。预览 / 输出清单保存触发段索引、原因及调整数量，写入仍只生成新副本。

实测：对比用户“部分修复”存档与生成档，58 个节点由地面改为 +1；相同生成方案的本地检测覆盖全部 58 个节点。用户只修了部分区段，因此此覆盖率不是所有游戏冲突的检出率，且不代表输出已在游戏内建造验收。[游戏层级规则](https://wiki.nimbyrails.com/How_to_build_track)。

## 自动发现与依赖

### 只选首尾站，识别沿途已建站 / 蓝图站

在自动模式中选定存档里的完整首尾站名，点击“识别首尾之间的沿途站”。工具先沿本地铁路底图寻路，再将距这条路径 200 米内的存档车站按沿线里程排列；只扫描站点注册表中的对象，不读取现实车站 POI、不创建新车站、不修改存档。已建站和蓝图站一起作为候选，不推测或标注建设状态。

候选默认不勾选，显示站名、ID、沿线里程和距路径距离。同名不同 ID 不合并；路线回绕而导致站点接近多处时显示站序核对提示。距离近不能证明属于同一条铁路，平行线、换乘及分支站请手动确认；远离路径的站不会列出，也不保证找齐所有途经站。

勾选 1–38 站并确认替换途经站列表后，按沿线顺序填入，再点击“检查冲突并预览”。原手动途经站不参与首尾寻路；替换仅影响工具箱方案，不删除游戏车站。修改参数会清除待确认候选；识别后存档改变会阻止生成，须重新自动读取并识别。新预览会按选中站逐段重新寻路，路线可能变化，须核对预览；站台接口、信号仍需游戏内处理。

Armstrong → Winnipeg 本机样本可直接按首尾寻路：约 628.3 公里，读取 1024 个实际地图块、约 3.96 MB 压缩数据，寻路约 1.9 秒。存档沿途有 19 个候选车站，确认加入后成为 21 站 / 20 区间方案，20 段均通过预览，6978 个双轨节点，包含水域 / 道路预避让；完整分段预览本机复测约 70 秒。不能忽略中途已建站台直接覆盖铺轨；站台接轨空隙仍保留，Elma → Winnipeg 额外桥隧退让在预览中列明。此为代码预览及写后内存回读验收，未在游戏内验收，也未覆盖原档。

此按钮不再设首尾 100 公里上限。两站矩形超过 4096 瓦片，或附近扩展搜索仍找不到路时，自动改为从两端沿铁路穿出地图块的位置继续探索，再验证实际铁路连接；不会仅因矩形面积大直接退出。仍保留至少 0.1 公里、实际处理量和局部坐标范围检查，不是全球无限范围寻路。达到实际处理上限时分批选择首尾，或添加途经点。零候选时可保留原途经站，直接使用普通预览，不会清空已有列表。存档内没有名称的站按唯一 ID 显示，不会自动改名。

### 底图与运行组件

- 优先读取 Windows Steam 注册表和 libraryfolders.vdf；兼容常见其他盘 SteamLibrary、Linux Steam 和 macOS Steam 路径。
- 未找到或有多个安装时，在页面填写游戏本地 osm400.pmtiles 路径；不访问远程地图服务。
- 自动寻路需要 **Node.js 22 或更新版**。v1.7.0 免安装 EXE 包已内置，无需自行安装；源码版使用本机运行时或 runtime/node.exe / runtime/node。工具不会在运行时静默下载或安装依赖。没有它仍可使用原型和 GeoJSON 路线。
- GeoJSON 自动扫描：存档目录、存档目录下的 routes、工具箱 routes。只列出不超过 500 KB 的地理数据，排除普通时刻表 JSON；最多展示 200 份，按修改时间排序。手动导入保留为备用。
- PMTiles + MLT 解码器已随包提供，无需用户执行 npm 或安装 Python 地理库。许可与构建说明见 third_party/autotrack/。

## 范围与拒写条件

- 当前写入格式为 NIMBY Rails **1.19.10**；必须完整识别轨道注册表、所有节点及下一对象表，槽位连续。其他版本或未知轨道记录拒写。
- 覆盖三种**内置**轨道，不承诺任意工坊轨道。每次写入前核对存档实际内置定义及编号，不靠假定序号套模板。
- 单段路线及多站方案总长均不再设 150 公里上限；单段路线至少 0.1 公里，最多 4000 个中心线点，双轨间距固定 5 米。仍按局部坐标计算，不支持跨日期线。
- 自动寻路不再设两站 100 公里上限，直线距离至少 0.1 公里；取消距离限制不等于无限范围寻路，底图读取量、局部坐标、节点及冲突检查仍保留，超出时需分段。
- 多站方案最多 40 站，所有成功区间合计不超过 8000 个双轨节点。超过节点上限请分批；不支持重复站点/坐标的往返重叠方案。逐段进度显示于后台任务栏；预览期间不创建存档。
- 小范围寻路取两站包围区域并扩展 3 / 8 / 16 / 32 公里，复用已读取区域；矩形超过 4096 瓦片或附近搜索耗尽后改为铁路分块搜索。分块模式每批最多 256 个实际地图块，从两端的 500 米贴合邻域开始，优先探索靠近两端连线的铁路延伸，但允许绕行。地图块邻接只用于决定读哪里，绝不直接当成轨道连接；最终仍验证类型、层级、桥隧及轨道顶点路径。
- 小范围阶段最多 120 秒；铁路分块阶段最多实际探索 16384 块、256 MB 压缩读取、10 万条铁路要素、3000 万字符解码数据，使用 240 秒的解码与阶段间时间预算。每个解码进程最多 90 秒、512 MB Node 堆。分块阶段按实际访问计数，不按两站矩形面积计数；进度显示处理量而非预计完成比例。达到上限会明确报告搜索未完成，可增加途经点。不做全球全量扫描，不承诺找到全球最短路线。
- 站点吸附底图最大 500 米，实际距离展示在预览中。优先使用最近边；自动模式发现两端不连通时，尝试两端都能接入的同类型网络，按最大/总吸附距离优先选择，并显式提示回退。不跨越断口猜连接；多线并行时请核对类型及路线。
- 不在几何交叉处制造路口。普通端点保留 2 个 z14 坐标单位的拼接阈值；相邻瓦片接缝通常允许最多 3 个单位（赤道约 1.8 米，随纬度缩小）的量化误差，但必须位于对应边界、类型 / 层级 / 桥隧一致、内向切线相反且偏差不超过 15°，并且双方都只有一个候选连接。针对斜穿边界导致的误差放大，仅当相对两侧轨道切线的横向误差均不超过 1 单位、方向偏差不超过 3° 时，才允许边界偏移放宽到 8 单位。有歧义的平行线、不同层、超出条件的断口仍拒绝连接；制图底图不能证明真实工程连通性。
- 分块探索用确定性优先队列，避免每读取一块就重排全部候选；路网扩大时逐步降低完整建图频率，探索结束或到达块数预算前始终再检查一次。只有一种铁路类型时，不重复建立完全相同的回退路网。不会因此改变最大读取量或绕过安全校验。
- 桥隧端点可连接到制图折返线的明确汇合顶点，但必须坐标完全重合、铁路类型一致、层级差不超过一层、只有一个兼容地面顶点，并且所有相邻方向均与桥隧方向相反且偏差不超过 15°。普通穿越、不同层、间隙和有歧义的交会不适用。取消原先误用的 6° 经度跨度门槛，仍拒绝跨日期线，保留节点数和单边长度上限。
- 自动避让既有轨道产生的裁剪端点若落在桥隧中，向生成区间内部退至结构外并保留接轨预留；只会减少新增蓝图，不延伸进已占用轨道。预览警告和 `structure_trim` 字段列出额外空隙，需要游戏内手动接轨。手动指定在桥隧中切断、或退让后不足 100 米仍拒绝生成。
- 直读优化复用已读入的压缩快照，仍核对原文件变化。原生压缩 / 解压直接引用不可变输入，只复制有效输出；节点专用读取保留全量记录校验，但省去地图线段与汇总距离的构造。本机约 34.5 MB 解压数据样本中，解压约 0.065 秒，改善很小；压缩约 0.213 → 0.185 秒，压缩调用新增分配峰值约 111 → 42 MB（不是进程总内存）。55637 个节点的直读结果与完整几何读取相同，约 1.25 → 1.10 秒。速度因存档与机器负载变化。
- 存档加载先在底层快速查找轨道记录候选，再逐条完整解码校验；车站目录只扫描一次注册对象候选，不再为每个车站重扫整份数据。同一次任务最多缓存一份不可变解压数据的轨道表与布局，按字节对象身份绑定；生成下一版数据后重新独立回读，回读结果可供下一段复用。任务结束（含异常）清除缓存，不跨文件、跨任务或以修改时间猜测复用。
- 历史性能基线（桥隧自动退让改进之前）：Hornepayne → Armstrong 约 393.3 公里，读取 512 块、约 0.79 MB 压缩数据，2 次解码与建图约 0.7 秒。含水域 / 道路检查的 8 段预览由约 61 秒降至约 23 秒；完整轨道解析由 17 次减至 8 次（原档一次，7 个成功区间各独立回读一次）。51149 个轨道节点、542 个车站及完整预览 JSON / 指纹一致。当时 Ferland → Mud River 因桥梁裁剪而拒绝；当前结果以新预览为准。耗时不是所有机器或存档的保证，既有轨道保护导致的拒绝也不等于寻路失败。
- 生成路径后可移除数值上共线的冗余中间点，横向容差仅 0.01 毫米，保留桥隧节点和最长 1500 米的边；不为凑节点上限拉直真实弯道。4000 中心线点 / 8000 双轨节点的写入保护仍保留。
- 已建轨道和待建蓝图都参与直线近似冲突检查。端部避让后默认再留 50 米（可设 20–200 米）；玩家设施避让关闭时，中部冲突仍拒绝，跨层相交也可能保守拒绝。开启方式及近似限制见下节。
- 桥隧标记是底图分类，+1 / -1 是游戏离散层级，不是测量高程或自动地形适配。
- 预览绑定存档、参数、路线内容与底图文件状态；改变后须重新预览。写后回读连接、类型、层级、坐标，并验证压缩往返，旧轨道和非轨道对象流逐字节保留。

## 玩家轨道 / 车站预避让

在自动结构模式下，选择“玩家轨道 / 车站预避让”的向上 +1 或向下 -1；默认关闭，与水域 / 道路选项独立。只将新蓝图的冲突地面控制点调整到指定层，已经分层的交叉保持不变；不移动、拆除或更改原有设施。桥梁 / 隧道沿用各自选定的速度类型。首尾接轨预留依旧生效，不自动接入站台。

- 读取同一存档的已建及蓝图轨道，包含站台轨道；按节点连线及 15 米缓冲区近似，不是游戏曲线或实际净空模型。高低层节点之间按中点分半检查，调整后重查所有接近路段，防止新产生邻段冲突。
- 车站另以地面中心保护圈近似，半径默认 60 米，可选 10–200 米；不含当前区间首尾站（ID 或坐标匹配），但这些站的轨道仍检查。目录包含已建 / 蓝图站，不臆测站房建设状态、实际轮廓或高度。需要停靠的中途站应加入途经站，不能用上跨或下穿代替接站。
- 仅解释已核验的地面、+1、-1 层。接近未知层轨道、目标层仍占用、原底图桥隧冲突、或水域 / 道路避让与玩家设施要求相反时，拒绝该区间并提示分段或换方向；不会继续升到 +2、降到 -2，也不覆盖既定桥隧。
- 预览警告列出接近轨道 / 蓝图 / 车站保护圈的段数和实际调整节点数，悬停线段可查看检查原因。数量指候选路段，不是冲突设施总数，已经分层的接近段也会计入。
- 仍需在新副本内验收坡度、净空、曲线与建筑冲突。代码测试及二进制回读不代表游戏建造成功。未读取其他建筑、信号设施完整碰撞体，也不声称全部避让。

## GeoJSON 备用格式

一条连续 LineString，或包含一条中心线的 FeatureCollection，不直接接受未排序多段线网。
相邻点 0.05–2000 米；过密点会提示在游戏中检查。桥隧为单独 LineString，
properties.kind=structure，brunnel=bridge|viaduct|movable|tunnel，两端须与中心线节点对应；结构不得重叠。

输出使用 _Autotrack_日期_时间.nimbyrails5 与独立清单。通过临时文件和排他发布保证不覆盖已有文件。
自动清理仅识别清单完整且输出哈希仍匹配的工具副本；玩家在游戏中续存过的副本不自动删除。
