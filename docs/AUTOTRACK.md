# 自动铺轨（实验）

按起点、途经站、终点的顺序，沿游戏本地矢量铁路逐段寻找路线，生成**待建双轨蓝图**。
不是任意两点都一定有路：底图必须有连续路径，且满足范围、存档结构和冲突检查。
不改既有站台、道岔和信号，两端保留接轨空隙，最终接轨及工程验收仍在游戏中完成。

## 第一次操作

1. 在总览选择刚保存的存档，再打开“自动铺轨 · 实验”。首次展示四步教学，以后可点“使用教学”重看。
2. 自动读取当前存档站点、Steam 库的 osm400.pmtiles 和本地 GeoJSON 路线。
3. 路线来源选“自动”。搜索起终站，选择包含 ID 的完整结果；同名站按 ID 区分。地图上尚未建站可输入 经度,纬度，例如 -73.5561007,47.8575037。
   需要沿线多站时，点“添加途经站”，从上到下填写站序；可上移、下移或删除，最多 18 个途经站（总共 20 站）。多站模式逐段使用全长，起终里程裁剪暂不适用。
4. 选择现实铁路过滤器；默认包括铁路、轻轨、地铁、电车、窄轨、单轨和缆索铁路。底图未收录的类型不会凭空出现。
5. 结构默认“自动”：无桥隧标记时使用地面，有标记时保留桥梁 +1 / 隧道 -1 层。也可强制整段地面、高架或隧道。
6. 地面、桥梁、隧道分别选择中速 160 / 高速 350 / 电车 60 km/h，默认均为中速。这里只是轨道类型上限，不保证曲线上的实际速度。
7. 点击预览，检查每个相邻站区间的路线、站点吸附距离、桥隧、避让及警告。失败区间会单独列出原因，成功区间仍显示在地图上。部分通过时，勾选“仅生成通过区间，跳过未通过区间”，再确认游戏内验收提示，即可把剩余区间蓝图一次写入一个新测试存档。失败区间整段留空，不会跨过失败站点或用直线补连；全部失败时不能生成。
   也可在失败区间下删除相关站点，或修改坐标、铁路类型，再重新预览。删除仅从方案移除，不会删除游戏内车站，但会重新连接它前后的站；这与保留缺口的“部分生成”不同。改参数会清除部分生成确认，不能复用旧预览。
   后续区间会避让前面准备生成的轨道；各站附近可能留有空隙，仍需游戏内手动接站和信号。失败原因可能来自底图断路或轨道冲突，不一定是该站本身的问题。写入时再次核对预览指纹；底图中途改变、存档结构未知或预览变化不能用“部分生成”绕过。
8. 游戏内保存现有进度，加载新副本，暂停检查弯道、坡度、净空、桥隧边界，再小范围试建、手动接轨和配置信号。

例如 A→B 通过、B→C 失败、C→D 通过：部分生成只生成 A→B 和 C→D，两段之间保持断开。生成结果和同名 `.manifest.json` 清单记录通过的区间编号、跳过的起终站及原因。编号字段 `index` 从 0 开始，界面编号从 1 开始。“导出预览方案”保存的是 JSON 报告，不是可直接在游戏中加载的蓝图；可加载的蓝图位于生成的新 `.nimbyrails5` 存档中。

部分生成以相邻站点区间为单位。单一区间中部存在冲突时，不会擅自切碎该区间、跳过未知结构或截断桥隧来强行生成；可增加合适的途经点或调整范围后重新检查。

耗时读取、寻路和写入在后台运行，不弹终端。写入阶段禁止强制取消。不会上传存档或底图，不会覆盖输入。
教学已读状态保存在工具箱用户设置目录，不依赖浏览器随机端口；更新后仍保留。

## 自动发现与依赖

### 只选首尾站，识别沿途已建站 / 蓝图站

在自动模式中选定存档里的完整首尾站名，点击“识别首尾之间的沿途站”。工具先沿本地铁路底图寻路，再将距这条路径 200 米内的存档车站按沿线里程排列；只扫描站点注册表中的对象，不读取现实车站 POI、不创建新车站、不修改存档。已建站和蓝图站一起作为候选，不推测或标注建设状态。

候选默认不勾选，显示站名、ID、沿线里程和距路径距离。同名不同 ID 不合并；路线回绕而导致站点接近多处时显示站序核对提示。距离近不能证明属于同一条铁路，平行线、换乘及分支站请手动确认；远离路径的站不会列出，也不保证找齐所有途经站。

勾选 1–18 站并确认替换途经站列表后，按沿线顺序填入，再点击“检查冲突并预览”。原手动途经站不参与首尾寻路；替换仅影响工具箱方案，不删除游戏车站。修改参数会清除待确认候选；识别后存档改变会阻止生成，须重新自动读取并识别。新预览会按选中站逐段重新寻路，路线可能变化，须核对预览；站台接口、信号仍需游戏内处理。

此按钮不再设首尾 100 公里上限，但仍保留至少 0.1 公里、每个区间最多 4096 瓦片及局部坐标范围检查。找不到路时逐步扩大搜索，新增区域分批读取；不是全球无限范围寻路。范围过大时分批选择首尾，或在实际绕行处手动添加途经点。零候选时可保留原途经站，直接使用普通预览，不会清空已有列表。

### 底图与运行组件

- 优先读取 Windows Steam 注册表和 libraryfolders.vdf；兼容常见其他盘 SteamLibrary、Linux Steam 和 macOS Steam 路径。
- 未找到或有多个安装时，在页面填写游戏本地 osm400.pmtiles 路径；不访问远程地图服务。
- 自动寻路需要 **Node.js 22 或更新版**。v1.7.0 免安装 EXE 包已内置，无需自行安装；源码版使用本机运行时或 runtime/node.exe / runtime/node。工具不会在运行时静默下载或安装依赖。没有它仍可使用原型和 GeoJSON 路线。
- GeoJSON 自动扫描：存档目录、存档目录下的 routes、工具箱 routes。只列出不超过 500 KB 的地理数据，排除普通时刻表 JSON；最多展示 200 份，按修改时间排序。手动导入保留为备用。
- PMTiles + MLT 解码器已随包提供，无需用户执行 npm 或安装 Python 地理库。许可与构建说明见 third_party/autotrack/。

## 范围与拒写条件

- 当前写入格式为 NIMBY Rails **1.19.10**；必须完整识别轨道注册表、所有节点及下一对象表，槽位连续。其他版本或未知轨道记录拒写。
- 覆盖三种**内置**轨道，不承诺任意工坊轨道。每次写入前核对存档实际内置定义及编号，不靠假定序号套模板。
- 单段路线及多站方案总长均不再设 150 公里上限；单段路线至少 0.1 公里，最多 4000 个中心线点，双轨间距固定 5 米。仍按局部坐标计算，单段经度跨度须小于 6°，不支持跨日期线。
- 自动寻路不再设两站 100 公里上限，直线距离至少 0.1 公里；取消距离限制不等于无限范围寻路，底图读取量、局部坐标、节点及冲突检查仍保留，超出时需分段。
- 多站方案最多 20 站，所有成功区间合计不超过 8000 个双轨节点。超过节点上限请分批；不支持重复站点/坐标的往返重叠方案。逐段进度显示于后台任务栏；预览期间不创建存档。
- 寻路先取两站包围区域并扩展 3 公里，未找到连续路径时再尝试 8 / 16 / 32 公里。复用已读取区域，只分批读取新增边缘，每批最多 1024 瓦片。每个区间累计上限：4096 瓦片、256 MB 压缩读取、10 万条铁路要素、3000 万字符解码数据；解码及阶段间检查使用 120 秒总时间预算，每个解码进程最多 90 秒、512 MB Node 堆。达到上限会说明搜索未完成，不直接断言现实铁路不连通；可在绕行处增加中间站。不做全球全量扫描。
- 站点吸附底图最大 500 米，实际距离展示在预览中。优先使用最近边；自动模式发现两端不连通时，尝试两端都能接入的同类型网络，按最大/总吸附距离优先选择，并显式提示回退。不跨越断口猜连接；多线并行时请核对类型及路线。
- 不在几何交叉处制造路口；瓦片端点仅在约 1 米内保守拼接。制图底图缺少可靠拓扑，可能拒绝现实上相连的线路，也不能保证每个道岔均真实可通行。
- 已建轨道和待建蓝图都参与直线近似冲突检查。端部避让后默认再留 50 米（可设 20–200 米）；中部冲突拒绝。跨层相交也可能保守拒绝，不自动绕过。
- 桥隧标记是底图分类，+1 / -1 是游戏离散层级，不是测量高程或自动地形适配。
- 预览绑定存档、参数、路线内容与底图文件状态；改变后须重新预览。写后回读连接、类型、层级、坐标，并验证压缩往返，旧轨道和非轨道对象流逐字节保留。

## GeoJSON 备用格式

一条连续 LineString，或包含一条中心线的 FeatureCollection，不直接接受未排序多段线网。
相邻点 0.05–2000 米；过密点会提示在游戏中检查。桥隧为单独 LineString，
properties.kind=structure，brunnel=bridge|viaduct|movable|tunnel，两端须与中心线节点对应；结构不得重叠。

输出使用 _Autotrack_日期_时间.nimbyrails5 与独立清单。通过临时文件和排他发布保证不覆盖已有文件。
自动清理仅识别清单完整且输出哈希仍匹配的工具副本；玩家在游戏中续存过的副本不自动删除。
