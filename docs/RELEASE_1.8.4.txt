NIMBY Timetable Toolkit 1.8.4

自动铺轨：识别沿途已有车站
- 选择当前存档中的完整首尾站名，点击“识别首尾之间的沿途站”。工具先沿本地铁路底图寻路，再列出距路径 200 米内的已建站 / 蓝图站候选，按沿线里程排序。
- 显示站名、唯一 ID、沿线里程和距路径距离；同名站不合并，靠近路径多处的站提示核对站序。
- 候选默认不勾选，选择 1–18 站并确认替换途经站列表后，再预览生成。不会创建现实车站，也不会自动接入站台、添加道岔或信号。
- 距离近不等于属于同一条铁路，平行线、分支及换乘站仍需人工确认。已建站和蓝图站一起读取，不推测建设状态；识别后存档改变将阻止使用旧结果。

距离限制与部分生成修复
- 取消首尾直线距离 100 公里、单段及多站方案总长 150 公里的硬限制。
- 仍保留最短距离、1024 瓦片读取范围、资源用量、20 站、8000 双轨节点、局部坐标及冲突检查；不是无限范围寻路，超出时仍须分段，不支持跨日期线。
- 修复“仅生成通过区间”的确认值未传递到后台，导致界面确认后仍无法部分生成的问题。
- 更新教学和操作说明，明确蓝图在新测试存档中，JSON 预览报告不是可加载蓝图。

副本与旧导出清理
- 手动清理新增游戏时刻表导出 JSON、工具箱线路图 JSON 两种可选范围；先预览，再逐文件勾选并确认移入 Windows 回收站。
- 工具副本和时刻表按项目保留最新指定份数；地图按线路选择及绘图设置分组。补充多层工具时间后缀及 StopTime30s 等停站时长副本、临时文件识别。
- 当前总览 / 历史对比选中的文件和永久保留文件受到保护；执行前重新核对内容摘要，拒绝已变化的预览、名单外目标和正在运行的后台任务。
- 启动自动清理仍只处理核验通过的工具副本与过期临时文件，不包含 JSON 导出。JSON 默认不勾选，“较旧”不代表一定无用。
- JSON 扫描仅限存档目录和当前地图导出目录中的指定格式，单文件最多 50 MB；不扫描子目录、未知 JSON、地图 SVG / TXT 或自定义时刻表草稿。
- 回收站中的文件可恢复，但仍占磁盘空间；本版不自动执行一次全面清理。

升级与验收
- 提供 Windows x64 免安装 EXE 包，内置 Python、Node.js 和桌面组件。
- 已有更新按钮的便携版可点击“检查更新”，确认后下载并安装；校验 ZIP SHA-256 与逐文件清单，不覆盖游戏存档或个人设置。
- 更新前保存工具箱内未完成的工作，并关闭多余的旧工具箱实例。源码 / Git 工作区不会被自动更新器覆盖。
- 自动铺轨仍为实验功能，需加载新副本，在游戏中检查线形、接轨、净空和实际运行。
