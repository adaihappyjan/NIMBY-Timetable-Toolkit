# 副本与旧导出清理

进入“副本清理中心”，设置天数与每组保留份数，按需要勾选旧时刻表 / 线路图 JSON，然后点击“刷新清理预览”。核对名称、完整路径和理由，勾选不再需要的文件，再点击“将勾选文件移入回收站”。确认框显示勾选数量和大小。预览本身不移动文件。

## 支持的文件

- 工具时间副本及同名生成清单：支持 Toolkit、Extension、Recovery、Repair、Workspace、Autotrack、Names、StopTime、StopTimes、StopTime30s 等停站时长名称、GarageJoin、Align。必须有匹配的输出路径和 SHA-256。玩家后来覆盖保存、记录缺失或同名 `.keep` 永久保留时跳过。
- 中断写入的 `.nimbyrails5.partial`：仅接受上述工具时间命名，超过一小时才列出；最近的临时文件保留。
- 游戏时刻表导出：仅存档目录中的“项目名 Timetable Export YYYYMMDDTHHMMSSZ.json”，且内容具有 Line / Schedule 对象；不同项目分别保留最新指定份数。
- 工具箱线路图 JSON：仅存档目录和当前配置的地图导出目录，校验 `nimby-toolkit-line-map.v1`、线路及车站结构。不同线路选择和绘图设置分别保留；不是清理 ORM 瓦片缓存。

JSON 扫描只处理不超过 50 MB 的文件，不扫描子目录、历史上使用过的其他导出文件夹或任意 JSON，不处理地图 SVG / TXT、自定义时刻表草稿。格式识别只表示这是可供检查的导出，不代表文件一定无用；候选默认不勾选。

## 保留与保护

“按天数”要求旧文件既超过天数又超出保留数量；“立即瘦身”忽略天数，但仍至少保留每组一份。工具副本按原始项目名分组，连续在副本上生成的多层时间后缀会归回同一项目。无记录的文件不会仅凭名称被补认为已验证副本。

总览和历史对比中当前选中的存档 / JSON 不列入手动清理；同名 `.keep` 文件也会保护对应文件。程序不能知道游戏或外部编辑器正在使用哪份文件，请先保存并确认用途；对重要副本使用“永久保留”。

执行前重新计算名单及内容摘要；修改内容、改名、添加保护或改变设置会使旧预览失效。只处理重新核对后的勾选项，拒绝名单外路径、符号链接和范围外文件。工具箱后台任务正在使用文件时拒绝清理。移入回收站后可通过 Windows 回收站恢复，不承诺立即释放磁盘空间。

启动自动清理默认关闭。启用后仅使用副本及临时文件规则，不把手动勾选的 JSON 类别保存为自动删除规则。若 Windows 报告移入回收站失败，请检查错误；不会退回永久删除。
