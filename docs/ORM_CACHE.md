# ORM 本地地图缓存

工具箱左侧「ORM 地图缓存」可以启动独立后台服务。默认地址：

```text
http://127.0.0.1:58743/tiles/standard/{z}/{x}/{y}.png
```

在游戏「地图选项 → 数据源 → 新建数据源」中填入地址，来源选择 HTTP，
数据格式选择「通用栅格」。名称可填「ORM 本地缓存」。启用后关闭原有同类在线 ORM
图层，避免重复请求。此功能不写游戏存档；游戏端实际显示仍需手动验证。

## 随游戏启动（Windows）

点击「开启随游戏启动」：在**当前用户**的 Windows 启动文件夹创建专用快捷方式，
目标为已安装 Python 的 `pythonw.exe`，运行 `toolkit_tilewatch.py`。立即启动检测器，
之后每次 Windows 登录也会启动。每 5 秒只读检查 `NimbyRails.exe` 进程名；
检测到游戏启动后开启缓存，**不需要先打开工具箱，没有黑色终端窗口**。

- 不注入游戏，不修改 Steam 启动参数，不需要管理员权限。
- 启动失败最多每分钟重试一次；缓存停止按钮会被尊重，本次游戏会话不自动拉起。
- 游戏退出不会强制关闭缓存，避免影响其他地图使用者。
- 点击「关闭随游戏启动」会删除本功能自己创建且带有标记的快捷方式，
  检测器随后自动退出，已运行的缓存仍可手动停止。
- 不要移动/删除工具箱文件夹；如果移动了，请在新位置重新开启此选项以更新快捷方式。
- 「随工具箱启动」是独立选项，不等于「随游戏启动」。

## 缓存与清理

默认内容上限 2048 MB，清理 90 天未使用的瓦片。SQLite 数据库保存于设置目录
`map-cache/nimby-orm-cache-v1/tiles.sqlite3`；目录可在服务停止后修改，旧库不自动搬迁或删除。
清理仅删除专用数据库里的瓦片记录并回收空页；数据库索引等有额外磁盘开销。
关闭工具箱不会关闭缓存，重启服务后仍保留瓦片。统计计数按本次服务运行计算。

仅在收到游戏当前视图请求时下载，不支持批量预取。过期瓦片按需使用 ETag/Last-Modified
检查更新；网络失败时可返回旧瓦片。离线模式仅使用已有缓存，不能补全未看过的区域或缩放级别。
HTTP 429 会暂停全部联网，并在重启后保留等待时间；不会将错误页面缓存为 PNG。

## 性能优化（缓存引擎 2）

- 最多两个下载任务并行，全局请求启动间隔仍为至少 0.5 秒；不以增加请求频率绕过限流。
- 同一瓦片的并发请求共用结果；最多 32 个不同瓦片任务待完成，每个请求最多等待 30 秒。
  等待超时且没有其他等待者时，取消尚未开始的任务，避免无用下载。
- 本地缓存命中不逐次提交写盘，访问时间每 10 秒或累计 1024 个不同瓦片批量写入；
  正常停止时也会刷新。意外断电最多丢失这段时间的访问时间记录，已提交瓦片不受影响。
- 内容容量使用累计计数，命中查询和状态查询不扫描整库。每 10 分钟进行保留期清理，
  或在内容超过上限时淘汰至约 95%，避免频繁清理。空闲页分批回收，磁盘占用可能稍后下降。
- 面板额外显示任务数、并行下载数、重复请求合并数、队列满、等待超时及平均耗时。
- 清空缓存时已在下载的图片可以返回给当前请求，但不会重新填入刚清空的数据库。

### 验证记录（2026-09-29）

全套测试 185 项通过、2 项跳过。覆盖重复请求合并、双任务并行与全局限速、
超过旧版 5 秒等待限制、队列超时取消、429 全局暂停、访问记录批量写入、
清理与下载竞争、启动检测及前端状态处理。测试不批量请求公共地图服务器。

本机升级时先备份 SQLite，逐块校验原有 7,531 块瓦片的 SHA-256，全部保留。
对已有且未过期瓦片进行 20 次本地 HTTP 读取，均命中缓存且内容一致，
本次响应中位数约 2.8 ms；此结果不是公网下载速度或游戏帧率保证。

图层名还支持 `maxspeed`、`signals`、`electrification`、`gauge`。
