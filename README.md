## 下载与启动

新增的**零基础 EXE 包**完整解压后双击 `NIMBYToolkit.exe`，无需安装 Python、Node.js、运行命令或使用管理员权限，也不弹出黑色终端。先阅读包内 `先看这里.txt`；打不开时双击 `故障诊断.exe`，它会生成并打开中文 TXT 报告。支持 Windows 10/11 x64（Intel / AMD），桌面窗口需要 WebView2；缺少时可退回默认浏览器。

请从 [Releases](https://github.com/adaihappyjan/NIMBY-Timetable-Toolkit/releases) 下载 v1.7.0 或更新版的 `portable` 附件，**不是 Code → Download ZIP 源码包**。旧源码入口 `启动工具箱.cmd` 继续保留：有 EXE 时优先使用它，否则查找本机 Python。

运行库在首次启动时校验并解压到 `%LOCALAPPDATA%\NIMBY_Timetable_Toolkit\runtimes`，不修改系统 Python 或 PATH。运行库下载地址和 SHA-256 固定在构建锁文件中，启动不需要下载依赖。发布构建与维护说明见源码目录中的 `scripts/零基础包构建说明.txt`。

**v1.6.0 内置安全自动更新。** 没有更新按钮的旧版本用户需手动下载并完整解压一次 v1.6.0；已有更新按钮的便携版可直接更新。以后启动时自动检查正式 Release，发现新版后点击“下载并重启更新”。工具会校验官方仓库来源、Release 版本、ZIP SHA-256 和逐文件清单，等待当前进程退出后替换；失败会尝试回滚旧文件。若回滚不完整，明确列出错误并停止自动重启，保留备份供恢复。存档和个人设置不参与更新。源码/Git 工作区不会被自动覆盖。自动检查可以关闭；安装始终需要用户确认。

界面由内置的本地服务提供，通过 pywebview 显示为一个原生窗口，不保留黑色终端窗口。关闭窗口会退出界面服务；如果已启动 ORM 缓存或开启随游戏启动，其独立后台服务会继续运行，可在「ORM 地图缓存」中关闭。

界面与本地服务只监听 `127.0.0.1` 的随机端口，并校验请求来源，其他网页无法驱动本工具。若本机缺少 pywebview 或 Edge WebView2 运行时，工具会自动退回“本地服务 + 默认浏览器”模式，功能一致。

仅**源码运行**需要自行安装 Python 3.10 或更高版本；EXE 包已内置依赖，无需执行下面的命令。源码版需要原生窗口时安装：

```powershell
python -m pip install -r requirements.txt
```

## 功能页一览

- **自动铺轨 · 实验**：选两个存档站点或经纬度，自动读取游戏本地矢量底图并寻路；自动发现 GeoJSON、首次四步教学。三种内置轨道（默认中速），地面 / 桥梁 / 隧道分别选速度类型。后台计算、彩色预览、重复与冲突检查、指纹校验、只生成新副本，不自动接站或添加信号。自动寻路需要 Node.js 22+；直线距离 0.1–100 公里、最多 1024 瓦片，断路不画直线替代，不支持任意工坊轨道。新版输出仍需游戏验收。详见 [自动铺轨指南](docs/AUTOTRACK.md)。
- **ORM 地图缓存**：为游戏提供本机 HTTP 栅格地图源，按需持久缓存标准/限速/信号/电气化/轨距图层。受限双任务下载、相同瓦片请求合并、访问时间批量写入、容量与保留期清理、离线模式及队列/超时统计。Windows 可选择随游戏启动，无需先打开工具箱；不预下载区域、不修改存档。见 [缓存与游戏联动指南](docs/ORM_CACHE.md)。
- **总览与体检**：选择存档和即时导出、查看健康分、严重问题与完整匹配状态，并显示自动识别的**游戏版本**（见下）。另含 **JSON-free 结构总览**：无需导出，直接从存档二进制直读并显示站/线/信号/车/时刻表/**标签分类**数、每张时刻表的分配列车数、色块与**单程运行时间**；以及 **JSON-free 逐站时刻表直读**：还原每条线路逐站到/发时刻与停站时长（时间以 0.5 秒精度存档，已用导出逐条校验，32/37 条线路含大部分地铁线精确到秒）。读取器已优化到秒级。
- **安全自动更新**：默认每 6 小时至多联网检查一次最新 GitHub Release；软件内一键下载、校验、关闭、替换并重启。校验覆盖固定官方仓库、精确资产名、版本号、SHA-256、ZIP 路径和每个文件的大小/摘要；安装前逐文件备份，异常则完整回滚。可在更新提示中关闭“启动时自动检查”，也可随时手动检查。详见 [自动更新安全设计](docs/AUTO_UPDATE.md)。
- **运营分析**：从导出 JSON 计算服务时段、班距均匀度、覆盖天数、车队规模等 KPI，可导出 CSV/JSON 报告（只读）。
- **JSON-free 运营估算（仅用存档体检）**：无需导出即可估算各线**班距**——基于实测规律 `h ≈ 单程循环时长 T ÷ 车数 N`（T、N 均从二进制直读）。因未计折返/层停，估算略偏小，实测**中位误差约 3.5%–5%、多数线路在 10% 以内**；若提供导出则作**只读真值护栏**逐条对账并显示误差与命中率；填目标班距还能规划各线**所需车数**。所有结果明确标注为“估算”。注：发车时刻/精确班距/覆盖天数由游戏运行时按规则展开、**不入档**，无法仅凭存档精确复现（详见 `docs/BINARY_FORMAT.md` §8.14）。
- **线路图**：按车站经纬度绘制单/多线路网图，自动识别换乘站；支持**地理示意 / 八向示意图（地铁图）/ 单线条形图（地铁贴纸）**三种风格，站名自动避让不重叠，可导出 SVG。线路颜色按游戏内配色（ABGR）还原。高级选项可自定义**标签字号、画布宽高、线路粗细、站点大小、站间距**并可一键重置。
- **现实路网**（含**现实路网导入向导**）：在真实世界地图上叠加 **OpenRailwayMap** 铁路数据，并把你游戏里的线路/车站画在同一坐标上；支持地点搜索、规划针（浏览器本地保存、导出 GeoJSON/CSV）。可从 **OpenStreetMap（Overpass）一键拉取真实车站**，也可**拉取真实线路（含按序站点）生成复刻对照清单**（线名/编号/类型/颜色/站数/近似里程/站序），导出 JSON/CSV，或把某条线的站点一键加入规划针。需要联网。
- **JSON-free 路网直读**（`toolkit_savereader.py`）：无需导出 JSON，直接从存档二进制读出整张路网——车站（id/名称/经纬度）、线路（名称/编号/颜色/**按序站点**）、信号与道岔节点（坐标）。站序与颜色已用导出 JSON 逐条对拹校验。现实路网页可“**从当前存档直读路网（含信号）**”并把信号/道岔上图。
- **JSON-free 真实轨道几何**（完整层级直读，只读）：导出 JSON **完全不含**轨道几何——现在仍可从完整存档还原。“现实路网”页可用 canvas 叠加真实轨道走向；解析器按**完整 Track ID、两个可空邻接、双向拓扑校验和全部结构/高度层级**读取，不再只认 level 0、不再限制存档前 6.5 MB，也不会裁掉合法长连接或远离车站的轨道。主存档实测 **21293 节点 / 18950 段 / 5741.6 km**，全部 37900 个有向引用均可解析且互为邻接。逐段限速/电气化/轨距等标量字段尚未逐一解，几何以节点直线相连近似（详见 `docs/BINARY_FORMAT.md` §8.15）。
- **车站坐标对齐**（`toolkit_coordedit.py`，二进制直读/就地编辑；亦可在现实路网页图形化操作）：无需导出 JSON，直接从存档枚举全部车站（id / 名称 / 经纬度），并把任意车站**就地改写为真实经纬度**做坐标级复刻。采用标准 Web Mercator（EPSG:3857，经零误差验证），只覆盖该车站坐标的 16 字节、payload 长度不变；只新建存档、反向解压校验、多命中/未命中一律拒写。
- **时刻表配置**：勾选智能匹配方案迁移到 Daily 模板；含均匀相位编排器、**班距规划器**与模板恢复。班距规划器基于实测规律 **线路班距 = 单车循环时间 ÷ 车数（`h = T/N`，实档 35/35 精确成立）**：设定目标班距即算出各时刻表所需车数与增减量（可导出 CSV），供你在游戏内加/减车——**零风险、绝不写存档**。
- **自定义运营时刻表编辑器**（`toolkit_scheduleconfig.py`）：直接显示并编辑每张时刻表持久化的 Order ID（已有只读保留、新增自动分配）、Line、Timing（准确到达／准确发车／不迟于到达）、Enter/Exit/Timing 站点、时间、日期、重复、继续状态和偏移组。支持在后插入、游戏原生的嵌套“堆积”、智能班距序列生成、冲突/旧 selector 检查、批量平移、10 组独立编辑及 v2 方案导入导出；时间支持半秒精度与次日 24:00–48:00。受控 `ORDER_INSERT/STACK` 与 `TIMING` 存档锁定了变长记录、全局 Order 分配器和线路 selector 表；写入只创建新存档，带原值回环、目标重解析、其它时刻表零波及和压缩反读校验。
- **车库接班**：按列车唯一 ID 批量加入或移除扩展，同名列车不会冲突。
- **批量绑定**（批量扩展绑定器）：一次为多条线路/多张车队生成 private mod（车库接班 / 到站附加等待 / 信号前分段限速）与逐对象清单（JSON/CSV）。二进制批量绑定只接受已验证的固定脚本 ID `stm_timetable_garage_join_1`：会先核对该脚本定义确实存在于存档，遇到 ID 不符、模组未启用保存或未知扩展向量一律拒写；成功时也只创建新存档。
- **车辆工坊**：按官方 `schema=2` 生成**可直接加载的车辆模组**。既有简易两端司机室表单，也有任意数量 `TrainUnit`、多套 `composition` 的高级 JSON 编辑器；覆盖加速度、制动、牵引力、功率、质量、载客、车门、联挂器和三类成本等完整字段。可只读扫描游戏内置、private mods 与 Steam 工坊，导入已有车型并检查重复引用、缺失贴图和 1024×128 尺寸；按游戏公开牵引公式预估满载性能和速度—加速度曲线。只生成新模组，从不改动来源或存档。
- **脚本规则**：生成车库接班、到站附加等待和**有明确生效距离**的信号前限速 private mod；生成前静态检查 meta/API、结构与回调对应、花括号、高频事件日志和无距离前瞻限速，并返回完整源码预览。静态检查不是游戏编译器的替代品，最终仍需在游戏内启用验证。
- **MCP Server**：`toolkit_mcp_server.py` 通过官方 MCP Python SDK v2 和本地 `stdio` 暴露 Order 结构说明、存档 Order List 只读检查、编辑/插入/堆积内存预演、新存档安全写入、车辆工坊扫描/生成和 NimbyScript 检查/生成。详见 [MCP Server 使用说明](docs/MCP_SERVER.md)。

## 游戏版本自动适配

工具分开核对存档头与导出的 `ExportMeta.model_version`，不能只凭 model 号推断存档写入兼容性。目前验证的写入格式是 **NIMBY Rails 1.19.10**（`NMBY 02 00 01 00 13 00 0a 00`），本机匹配导出的 model 为 230。

- **存档格式已验证**：允许进入现有写入流程，仍须通过对象、指纹和输出反读检查；不代表全部列车运行已验收。
- **未知存档格式**：可尝试只读检查，结果需复核；后端阻止写入，不能靠确认框绕过。
- **导出更新 / 未知 / 过旧**：单独显示提醒，不能把已识别的 model 当成新存档格式的写入许可。

写入只创建新存档，不覆盖原档。新版本必须经过样本核对、定向修改和反读测试，再加入 `toolkit_binary.py` 的已验证存档签名；不能只增加版本号。详见 [1.19.10 兼容说明](docs/COMPATIBILITY_1.19.10.md)。

批量配置预览期间修改参数、勾选或切换存档，会使旧预览作废，必须重新预览。后台任务运行时重复点击不会打断原任务的进度跟踪。“批量绑定”需要高级区域的 **深度核对（需导出）**，不是普通免 JSON 体检。

## 复刻现实路网

NIMBY Rails 使用真实经纬度，因此本工具可以把“现实”和“游戏”放在同一张地图上对照：

1. 打开 **现实路网**，用地点搜索或坐标跳转到目标城市。
2. 叠加 OpenRailwayMap 铁路层，看清真实线路与车站。
3. 点“**拉取此范围真实车站**”，把 OpenStreetMap 的真实车站导入为参考点。
4. 用“**全部加入规划针**”或手动点图放针，得到一份带坐标的复刻检查表；导出 GeoJSON/CSV，按坐标在游戏里逐站建设。
5. 打开“叠加游戏路网”，随时对照你已建成的部分与现实的差距。
6. 点“**从当前存档直读路网（含信号）**”，无需导出 JSON 即可把线路/站序/信号直接从存档二进制读出并画到地图上；勾选“**显示信号/道岔**”查看信号与道岔节点。
7. 勾选“**显示真实轨道**”（或点“直读真实轨道几何”），把存档里真实的轨道走向（曲线折线，非站点直连）叠加到地图上，用来对照真实线位建轨。

> OpenStreetMap / Overpass 是公共免费服务，有速率限制且偶尔繁忙；工具会依次尝试多个镜像，失败时请缩小范围或稍后再试。

### JSON-free 路网直读（无需导出）

现在可以完全跳过导出 JSON，直接从存档二进制读出整张路网（车站坐标 / 线路名·编号·颜色·**按序站点** / 信号·道岔坐标），经导出 JSON 逐条对拹校验站序与颜色：

```bash
# 直读路网概览（车站/线路/信号数量 + 前若干条线路）
python toolkit_savereader.py "存档.nimbyrails5"

# 输出完整 JSON（站/线含站序/信号）
python toolkit_savereader.py "存档.nimbyrails5" --json

# 直读真实轨道几何（节点数 / 段数 / 总公里 / 可绘折线段）
python toolkit_backend.py track-geometry --save "存档.nimbyrails5"
```

### 坐标级对齐（Web UI 或命令行）

把游戏里的车站**直接对齐到真实经纬度**（存档二进制就地编辑，无需 JSON）。

在 **现实路网** 页的“**把车站对齐到真实经纬度**”面板：先“从当前存档直读路网”，选一个车站，填目标经纬度或勾选“**点图取坐标**”后在地图上点一下，加入对齐列表，最后一键“**生成对齐后的新存档**”。也可用命令行：

```bash
# 列出存档里的所有车站（id / 名称 / 经纬度）
python toolkit_coordedit.py list  "存档.nimbyrails5"

# 把车站改写为真实经纬度，写入一份新存档（原档不动）
python toolkit_coordedit.py set   "输入.nimbyrails5" "输出.nimbyrails5" "Toronto Union Station=-79.380311,43.644512"
```

原理与安全性详见 [`docs/BINARY_FORMAT.md`](docs/BINARY_FORMAT.md)（存档二进制格式调查报告）：坐标为两个 float64 的 Web Mercator，改写只覆盖固定 16 字节、长度不变，写前做反向解压校验，遇到重名或找不到的车站会直接拒写。

清理现在分为两种：

- “自动规则”同时满足“超过天数”和“超出保留数量”才会移入回收站，并自动清理由工具留下超过 1 小时的 `.partial`。
- “立即瘦身”不等待天数，直接保留最新指定份数，把额外工具副本及对应清单移入 Windows 回收站。

所有目标都会先在界面中预览。正式存档、普通自动存档和非工具生成文件永不参与。

## 这次升级解决了什么

- 所有耗时操作都在独立后台进程中运行，窗口不再因为读取几十 MB 的 JSON、解压存档或压缩校验而假死。
- 底部显示实时进度和当前步骤，可随时点击“取消任务”。关闭工具时也会终止尚未完成的后台任务，不留下孤儿进程。
- 历史盘点和自动查找历史车队支持多核并行；可以在“历史与性能”页选择进程数。
- 真实文件基准：盘点 6 份导出时，1 个进程约 5.93 秒，4 个进程约 2.64 秒，提速约 2.25 倍。速度会随磁盘、文件大小和内存变化。
- 单份存档的修改与写入仍保持串行，避免多个核心同时改同一文件。
- 二进制解析与压缩支持已经收进工具箱目录，不再依赖开发时的 `work` 文件夹。Windows 便携包已内置并校验官方 64 位 `libzstd.dll`，整个解压后的文件夹可直接复制到别处使用，不再要求用户额外安装 Git for Windows 或自行寻找 DLL。
- 便携版加入应用内自动更新：自动检查官方 Release，一键下载并重启；每个发行包都生成 `.toolkit-manifest.json`，安装前同时验证 Release 校验和与全部文件摘要，替换失败会逐文件回滚。

## 五个功能页

### 智能批量配置

- 自动把已有时刻表与最可能的空白 Daily 模板配对。
- 一次迁移多支车队，也可以手动增删配对。
- 使用目标模板的指令结构重建班次，清空旧来源表，避免同一车队被两张表同时调度。
- 可同时确保整支车队启用 `Timetable garage join`。

### 车库扩展管理

- 一次勾选多张时刻表，批量加入或移除 `Timetable garage join`。
- 扩展目标按列车唯一 ID 定位；即使不同车队存在同名列车，也不会误选或重复命中。
- “只选风险项”会选中体检发现有严重问题或提醒的表。
- “修复严重车库循环”只修改导出数据已经证实为连续循环的单站车库指令，把重复方式改为 `x1`。
- “车库 x1 + 接班扩展”可在一次安全写入中同时完成两项处理。
- “修复旧表抢班”只针对体检确认的高重叠来源表/Daily 表组合，清空旧来源表并保留 Daily 表；有意的普通动态调度不会自动处理。
- 严重问题现在会变成右侧的“可修复任务”：旧表/Daily 重叠和连续车库循环可以分别勾选，也可以在一个新存档中一次修复。
- 如果 Daily 表缺日是由严重车库循环拖坏运行链造成的，任务会明确标注“车库 x1 后重新加载恢复日期”，避免重复修改本来已经是七天的日期掩码。

### 模板恢复

- 旧来源表已经被清空时，从历史 JSON 找回车队、班次 ID 和顺序。
- 实际运行内容始终取自当前空白模板，不会把历史坏循环重新带回来。
- “自动查找”会用多个后台进程并行检查最近的历史导出。

### 诊断与说明

体检现在区分显示：

- Daily 表缺少星期几；少量跨午夜运行不会被误算成完整的一天。
- 所有班次偏移均为 `0:00:00`。
- 部分班次使用了重复相位。
- 单站车库连续循环；普通的“每车每天一次”不会再误报。
- 有班次但没有列车、列车少于班次。
- 同一支车队仍同时被旧来源表和 Daily 表许可；动态调度虽然允许，但迁移后通常会造成抢班。
- 存档与导出 JSON 不匹配。
- 最后一张时刻表后面即使紧跟 Motion 或脚本数据，也只检查时刻表自身的记录，不会把后续数据误算成空表内容。
- 车库接班扩展的已启用、未启用和无法判断数量。

每条问题都带严重程度、所属时刻表和下一步操作。顶部给出健康分；只要存档与 JSON 未完全匹配，所有写入功能都会被禁止。

空白模板只是批量迁移的原材料，不是健康条件。所有 Daily 表都配置完成后，没有空白模板属于正常状态，工具不会再把它显示成故障。

完全没有班次的 `Daily` 表也会参与智能识别。例如 `TTC Line 2 Daily` 会匹配到 `TTC Bloor–Danforth`，但会显示为“待补模板”且不能勾选写入。先在游戏里给目标表建立 1 个未分配的模板班次，重新导出后即可直接迁移。这样能保留你设置的线路、车库路径和分组策略，避免工具凭空猜测运行逻辑。

### 历史与性能

- 并行盘点最近的存档、导出、校验记录和 `.partial` 中断残留。
- 显示每份导出的健康分、严重问题、空白模板数和耗时。
- 把“模板恢复”页选中的历史 JSON 与当前 JSON 对比，列出新增、删除和修改的时刻表，以及新增/已解决的问题。
- 后台进程数会保存，下次启动继续使用。

## 安全机制

- 永不覆盖输入存档；输出文件已存在时会停止。
- 每次写入前都会重新核对全部时刻表和全部列车；连“JSON 显示为空、存档实际仍有班次”的隐藏不匹配也会阻断。
- 先写 `.partial`，校验完整后再原子改名。
- 新存档会被重新读取、反向解压并校验 SHA-256。
- 每次生成 `.manifest.json`，记录输入、输出、修改内容、校验值和需要进游戏确认的事项。
- 定期清理只处理工具生成的 `Toolkit / Extension / Recovery / Repair` 时间副本和 `.partial`，并移入 Windows 回收站。
- 任务进度与结果通过系统临时目录传递，工具复制到别的位置后仍可运行。

## 推荐流程

1. 在游戏里保存一个待处理副本并导出当前时刻表 JSON。
2. 回到主菜单或关闭游戏。
3. 打开工具，点“自动选择最新文件”，核对文件名。
4. 点“扫描并检查”。先处理红色问题，确保顶部不是“存档与 JSON 不匹配”。
5. 选择迁移、恢复、扩展或安全修复，创建一个新存档。
6. 在游戏中加载新存档，检查偏移页、车库指令和调度状态。
7. 再导出一次 JSON，重新体检。确认健康后再自行决定是否替换正式存档。

## 关于偏移与车库

游戏的班次错峰由两部分组成：时刻表级分组策略，以及每个班次是否启用该自动分组。工具能从导出结果识别全零或重复相位，但在当前存档结构解析尚未完全稳定前，不会盲改时刻表级偏移策略。

迁移或模板恢复后，如果车队多于一列，清单会明确要求进游戏确认：

1. 偏移页的服务分组不是全部 `0:00:00`；
2. 自动分组按服务线路运行时长或预期固定间隔分配；
3. 单站车库指令显示 `x1`；
4. 重新导出后，工具体检显示相位正常且日期覆盖正确。

`Timetable garage join` 只放宽列车在车库中衔接下一班时的位置匹配。它不会自动发车、不会瞬移，也不能绕过轨道占用、站台冲突或错误信号进路。

## 仍然不能代替的操作

## 存档目录（换电脑 / 不同系统）

工具箱**不写死路径**，启动时会自动探测 NIMBY Rails 的存档目录，并支持随时手动切换：

1. **自动探测**：按优先级依次检查各系统的常见位置——
   - Windows：真实“Saved Games”已知文件夹（自动兼容 OneDrive 重定向）、`%USERPROFILE%\Saved Games\Weird and Wry\NIMBY Rails`、以及 `Documents\Saved Games\…` 等；
   - macOS：`~/Library/Application Support/Weird and Wry/NIMBY Rails`；
   - Linux 原生：`$XDG_DATA_HOME/…` 或 `~/.local/share/Weird and Wry/NIMBY Rails`；
   - Linux/Steam Proton：`…/steamapps/compatdata/1134710/pfx/drive_c/users/steamuser/Saved Games/…`。
   优先选中**真正含有存档**的目录。
2. **界面内切换**：首页“步骤 01 · 选择文件”下方有 **存档目录** 折叠面板，显示当前目录，可从探测到的候选一键切换，或直接粘贴自定义路径后点“应用此目录”。找不到时会自动展开提醒。选择会持久保存到本机配置（Windows: `%LOCALAPPDATA%`；macOS: `Application Support`；Linux: `~/.config`）。
3. **环境变量覆盖**：设置 `NIMBY_SAVE_DIR` 可强制指定目录（优先级最高，适合脚本/多人共用机，此时界面内不可改）。

> 所有写入始终只在**存档目录内新建文件**，绝不覆盖原存档。若该目录暂不存在，工具不会擅自创建空文件夹，只会提示你先选对目录。
